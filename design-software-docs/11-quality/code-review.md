## Objetivo

Definir el proceso de revisión de código para asegurar que las contribuciones cumplan los estándares de calidad, seguridad y mantenibilidad del proyecto.

---

## Flujo de revisión

El proceso recomendado es:

1. Desarrollo de la funcionalidad.
2. Creación de una rama de trabajo.
3. Apertura de Pull Request.
4. Revisión por al menos un integrante del equipo.
5. Corrección de observaciones.
6. Aprobación del Pull Request.
7. Integración en la rama principal.

---

## Criterios de revisión

Durante la revisión se debe validar:

- Cumplimiento de estándares de codificación.
- Legibilidad del código.
- Nombres claros para clases y métodos.
- Correcto manejo de errores.
- Ausencia de código duplicado.
- Uso adecuado de patrones de diseño.
- Seguridad de la implementación.
- Cobertura de pruebas.
- Actualización de la documentación cuando sea necesario.

---

## Lista de verificación

Antes de aprobar un Pull Request verificar:

- El código compila correctamente.
- Las pruebas son exitosas.
- No existen errores críticos.
- No se incluyen credenciales ni información sensible.
- La funcionalidad cumple los requisitos establecidos.
- La documentación fue actualizada cuando aplica.

---

## Herramientas recomendadas

| Herramienta | Propósito |
|-------------|-----------|
| GitHub Pull Requests | Revisión colaborativa |
| SonarQube | Calidad del código |
| JaCoCo | Cobertura de pruebas |
| Checkstyle | Estándares de codificación |

---

## Buenas prácticas

- Realizar revisiones frecuentes.
- Mantener Pull Requests pequeños.
- Documentar observaciones de manera clara.
- Resolver los comentarios antes de aprobar.
- Promover el intercambio de conocimiento entre los integrantes del equipo.

---

## Resultado esperado

El proceso de revisión de código contribuye a mantener un software más seguro, mantenible y alineado con los estándares definidos para el proyecto.
